# Healthy Life — памятка перед публикацией

## 1. Впишите свои данные (обязательно)

| Что найти | Где | На что заменить |
|---|---|---|
| `your-email@example.com` | index.html (2 места), legal.html, privacy.html, consent.html | Ваш адрес почты |
| `[ФИО владельца сайта]` | legal.html, privacy.html, consent.html | ФИО (или название ИП/организации) |

Быстрее всего — поиском с заменой по всем файлам (в VS Code: `Ctrl+Shift+H`).
Пока адрес не заменён, форма честно сообщает посетителю, что она ещё не подключена.

Для почты лучше выбрать российский сервис (Яндекс Почта, Mail.ru): закон требует хранить
персональные данные граждан РФ на серверах в России (ч. 5 ст. 18 152-ФЗ). Включите в почте
двухфакторную аутентификацию — это обещано в политике конфиденциальности.

## 2. Персональные данные (152-ФЗ)

Форма обратной связи собирает имя и e-mail, поэтому владелец сайта считается оператором
персональных данных. На сайте уже есть всё, что для этого нужно:

- политика обработки данных — `privacy.html`;
- отдельный документ согласия — `consent.html` (с 1 сентября 2025 года согласие должно
  оформляться отдельно от других документов);
- обязательная галочка согласия в форме, по умолчанию не отмеченная.

Что можете сделать только вы:

- **подать уведомление в Роскомнадзор** до начала сбора данных: pd.rkn.gov.ru (бесплатно, онлайн);
- выбрать **хостинг с серверами в России**;
- не подключать Google Analytics, Яндекс Метрику, виджеты соцсетей и т. п. без обновления политики
  (сейчас сайт не использует cookie и сторонние скрипты — поэтому баннер про cookie не нужен).

## 3. Что загружать на хостинг

Загрузить: `index.html`, `legal.html`, `privacy.html`, `consent.html`, `404.html`,
`style.css`, `script.js`, `theme.js`, папки `img/` и `hiper/`, а также
`.htaccess` (обычный хостинг с Apache) или `_headers` (Netlify, Cloudflare Pages).

**Не загружать:** `images/` (исходники фото, ~20 МБ, на сайте не используются),
`.claude/` (служебная папка для локального просмотра), `README.md`, `_config.yml` (нужен только для GitHub Pages).

## 4. Безопасность

Уже сделано в коде:

- **Content Security Policy** — браузер выполняет только скрипты и стили с самого сайта:
  внедрённый чужой код (XSS) не запустится. Политика стоит и в `<meta>` каждой страницы,
  и в заголовках сервера (`.htaccess` / `_headers`);
- **Trusted Types** и код без `innerHTML` — дополнительная защита от XSS;
- **запрет встраивания сайта в чужие страницы** (защита от кликджекинга);
- **HTTPS принудительно** + HSTS, `nosniff`, строгая политика Referrer, отключены камера,
  микрофон и геолокация;
- **ни одного внешнего скрипта, шрифта или счётчика** — нечего взломать «по цепочке поставок»;
- **внешние ссылки** открываются с `noopener noreferrer`;
- **форма**: ограничение длины полей, очистка управляющих символов, кодирование всех данных;
- **закрыт доступ** к служебным файлам (`.claude`, `.git`, `README.md`, исходникам фото) и к листингу папок;
- из фотографий при сжатии удалены метаданные (EXIF: модель камеры, возможные GPS-координаты).

Сделайте на стороне хостинга:

1. Включите HTTPS (бесплатный сертификат Let's Encrypt обычно включается одной кнопкой).
2. Поставьте сложный пароль и двухфакторную аутентификацию на хостинг и почту.
3. Проверьте заголовки после публикации: securityheaders.com или developer.mozilla.org/observatory.
4. Защита от DDoS — встроенная у хостинга или через прокси-сервис (например, DDoS-Guard).

Если сервер на nginx, добавьте в блок `server { ... }`:

```nginx
add_header Content-Security-Policy "default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; base-uri 'none'; form-action 'self' mailto:; object-src 'none'; frame-ancestors 'none'; upgrade-insecure-requests; require-trusted-types-for 'script'" always;
add_header Strict-Transport-Security "max-age=31536000" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "DENY" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "camera=(), microphone=(), geolocation=(), payment=(), usb=()" always;
add_header Cross-Origin-Opener-Policy "same-origin" always;
add_header Cross-Origin-Resource-Policy "same-origin" always;
server_tokens off;
autoindex off;
error_page 404 /404.html;
location ~ /\.(?!well-known) { return 404; }
location ~ ^/(README\.md|images/) { return 404; }
```

## 5. Авторские права и другие юридические моменты

- **Тексты** всех статей написаны заново своими словами; данные ВОЗ, NHS и др. пересказаны
  со ссылками на первоисточники. Прежний текст статьи о рекомендациях ВОЗ был скопирован
  с сайта ВОЗ почти дословно — его больше нет.
- **Фотографии** — с Pexels и Unsplash, это указано на `legal.html` со ссылками на лицензии.
  Лицензии разрешают бесплатно использовать и изменять снимки (мы их уменьшили) без указания
  автора. Чего делать нельзя: продавать фото без существенной переработки (постеры, принты),
  показывать людей на них в унизительном или оскорбительном виде, создавать впечатление, что
  эти люди или бренды на их одежде рекламируют сайт, собирать из снимков свой фотосток,
  делать фото частью логотипа или названия (раньше логотипом было `фото9` — сейчас оно не используется).
  Не используйте фото с людьми в рекламе: на это нужно согласие изображённых (ст. 152.1 ГК РФ).
  Новые изображения тоже берите только с фотостоков с такой же лицензией или снимайте сами —
  картинки из поиска Google/Яндекс использовать нельзя.
- **Название «Healthy Life»** может быть чьим-то товарным знаком. Перед продвижением проверьте
  базу ФИПС (fips.ru) по классам 41 и 44.
- **Медицинская оговорка** — в подвале каждой страницы и на `legal.html`.
- **Возрастная маркировка** 12+ (436-ФЗ) — в подвале.
- Если появятся реклама, продажи или платные услуги, понадобятся маркировка рекламы, оферта и т. п. —
  тогда стоит показать сайт юристу. Эта памятка не заменяет юридическую консультацию.

## 6. Как посмотреть сайт на компьютере и телефоне

Откройте `index.html` двойным щелчком — всё работает. Заголовки безопасности сервера при этом
не проверяются; для проверки в приложении Claude используется локальный сервер `.claude/serve.ps1`.

**На телефоне** файл `index.html` из скачанного архива нормально не откроется: мобильные браузеры
и просмотрщики файлов не подгружают соседние файлы (`style.css`, `script.js`, картинки), поэтому
страница выглядит почти пустой. На телефоне сайт нужно открывать по ссылке — см. раздел 7.

## 7. Бесплатная ссылка на сайт через GitHub Pages

Сайт уже лежит в этом репозитории в готовом для GitHub Pages виде. Чтобы получить ссылку:

1. **Сделайте репозиторий публичным.** GitHub → репозиторий → **Settings** → **General** → внизу
   **Danger Zone** → **Change visibility** → **Make public**. Для приватных репозиториев
   GitHub Pages работает только на платном тарифе.
2. **Включите Pages.** **Settings** → **Pages** → **Build and deployment** → **Source:**
   *Deploy from a branch* → в списке **Branch** выберите ветку с сайтом и папку `/ (root)` → **Save**.
3. Через 1–2 минуты сайт откроется по адресу
   **https://artyom1513.github.io/horrible-hobgoblin/** — эту ссылку можно открывать на любом
   телефоне и отправлять друзьям. После каждого нового коммита в выбранную ветку сайт обновится сам.

GitHub Pages удобен, чтобы показать сайт, но серверы GitHub находятся не в России. Пока форма
работает через почтовое приложение посетителя, данные через сервер не проходят, но для постоянной
публикации лучше выбрать российский хостинг (раздел 2).
